# Island: notes for coding agents

Island is a macOS-style Wayland desktop shell built on **Quickshell** (QML). It has a menu bar,
dock, desktop widgets, Spotlight, Launchpad, Control Centre, notifications, System Settings and
a lock screen, all in **one Quickshell process**. There's also an SDDM login theme in `sddm/`.
It's a personal setup that's also public (github.com/ItsFennik/island-dots), so keep it working
for the owner first. Don't strip their preferences to make it more generic.

Read `README.md` for the user-facing feature list, requirements and IPC list.
For any visual change, read `DESIGN.md` first: palette roles, type, shape and motion rules.

## Running it

| What | Command |
|---|---|
| Start / restart | `setsid -f qs -c island -n -d` |
| Logs (check after every edit) | `qs log -c island` |
| Drive it | `qs -c island ipc call <target> <fn> [args]` (targets: see `shell.qml` / README) |
| Screenshot to check a change | `grim out.png` (whole desktop) |

- **Never run `pkill -f "qs -c island"` from a shell.** The pattern matches the shell running
  the command, so it kills itself. To restart, kill the PID from `qs list`, or just start it
  again with `-n`.
- Quickshell **hot-reloads** on save. A QML error keeps the old version running and is printed
  in `qs log`. A clean reload ends with `Configuration Loaded`, and any `WARN` after that is yours.
- Test with IPC instead of guessing: `qs -c island ipc call menu controls`,
  `... picker themes`, `... lock preview` (shows the lock screen without locking), `... settings page NAME`.

## Layout

```
shell.qml          entry point: per-screen windows (Variants), LazyLoaders, every IpcHandler
bar/ dock/ widgets/ overlays/    surfaces (overlays = Spotlight, Launchpad, Overview, lock, screenshot UI)
popouts/           everything that drops down from the bar (opened through services/Popouts.qml)
settings/          System Settings: SettingsWindow.qml holds the data-driven page specs, pages/ the custom pages
services/          singletons (pragma Singleton): Config, Theme, Compositor, Popouts, Media, Audio, Net,
                   Notifs, Weather, SysStats, WallColors, WidgetLayout, … imported as `qs.services`
components/        shared controls (Switch, Slider, Segmented, MenuList, GlassSheen, …)
themes/*.json      colour palettes, one file each (themes/matugen.json is generated)
scripts/           wallpaper-set.sh, matugen-theme.sh, wallhaven.sh, screenshot.sh, …
apply-settings.sh  pushes settings to the compositor, GTK, Foot (runs after every settings save)
apply-theme.sh     pushes a theme to GTK/Kvantum, compositor borders, terminals, btop, cava, Vesktop, hyprlock
examples/<wm>/     compositor glue (autostart, keybinds, layer rules) for hyprland, niri, sway, mango
sddm/              login theme + install.sh
```

Folders are QML modules by directory (`import qs.services`, `qs.components`, `qs.bar`, …).
There are no qmldir files, and a new `.qml` file in a folder is picked up automatically.

## State outside the repo

| Path | What |
|---|---|
| `~/.config/island/settings.json` | the user's settings (only keys that differ from `defaults.json`) |
| `~/.config/island/theme-walls.json` | wallpapers paired with each theme (`{ "<theme id>": ["~/path", …] }`), read by `services/ThemeWalls.qml` |
| `~/.local/state/island/` | `wallpaper`, `theme`, `gtk-theme`, `workspaces`, `launcher.json`, `spotlight.json` (recent, launch counts, pins), `session-stamp` (boot:session already locked-on-start) |
| `~/.cache/island/` | video wallpaper posters (`video-thumbs/<md5 of path>.jpg`), fastfetch theme cache, other caches |
| Compositor configs | written by `apply-settings.sh`, e.g. `~/.config/mango/settings.conf`, `~/.config/hypr/…`. Files headed "Generated by … apply-settings.sh" get overwritten, so change the setting instead |

Find paths through `Quickshell.shellDir`, `Quickshell.env("HOME")` and the XDG variables.
**Never hardcode `/home/<user>` or `~/.config/quickshell/island`.** Some old code still
hardcodes it, and it should be fixed rather than copied.

## Theme pipeline

`apply-theme.sh <id>` reads `themes/<id>.json` and writes only files whose content changed:

| Target | File |
|---|---|
| GTK 3 | generated theme `~/.local/share/themes/Island` (adw-gtk3 + colours; re-read live on the theme-name blip) |
| GTK 4 | marked block in `~/.config/gtk-4.0/gtk.css` |
| Brave / Helium / Chromium | `BrowserThemeColor` policy in `/etc/{brave,chromium}/policies/managed/island.json` (live; folders made user-owned once); Brave new-tab background via `scripts/brave-ntp.sh` (while Brave is closed) |
| Kvantum | `~/.config/Kvantum/Island/` (via `scripts/kvantum-theme.py`) |
| Hyprland / Mango / niri / Sway | `theme.lua`, `theme.conf`, `island-theme.kdl`, `island-theme.conf` |
| Foot | `~/.config/foot/themes/island` |
| Kitty | `~/.config/kitty/themes/island.conf` |
| hyprlock | `~/.config/hypr/hyprlock.conf` (only used when Settings → Desktop & Widgets → Lock Screen → Locker is `hyprlock`) |
| btop | `~/.config/btop/themes/island.theme` |
| Cava | `~/.config/cava/themes/island` |
| Herdr / Vesktop | `~/.config/herdr-app/themes/island.json`, `~/.config/vesktop/themes/island.theme.css` |
| Neovim | repainted with `SIGUSR1`; colours come from `matugen.lua` reading the palette |

- The chosen id is stored in `~/.local/state/island/theme`; the bar and fastfetch read it.
- kitty/Neovim reload live; btop/cava pick the new theme up on next launch.
- starship uses ANSI colour names, so it follows whatever terminal palette is loaded.
- **Never hand-edit a generated file.** Change `themes/<id>.json` or the generator. `put` exists
  so repeated calls don't churn mtimes.

## Settings

- `Config.saved` = defaults merged with the user's file (applied). `Config.values` = saved plus
  staged edits (what Settings shows). Read `Config.saved.x` in surfaces and `Config.values` in
  Settings rows. Write with `Config.set(key, v)` (staged, autosaves after 450 ms) or
  `Config.commit(key, v)` (right away). Saving runs `apply-settings.sh`.
- **Adding a setting:** (1) a default in `defaults.json`; (2) a row spec in
  `settings/SettingsWindow.qml` (types: `switch`, `slider`, `choice`, `list`, `font`, `text`,
  `secret`, `wsstyle`, `button`; `when: "<key>"` greys it out; add search `keywords` to the page);
  (3) if it affects something outside Quickshell, handle it in `apply-settings.sh` and only
  rewrite a file when its content changes (`put`).
- Always read with a fallback: `Config.saved.foo ?? <default>`.

## Rendering and memory

- **Software renderer** (`QT_QUICK_BACKEND=software`, set in `shell.qml`). `ShaderEffect`,
  `MultiEffect`, `layer.effect` and GPU blur **do not work**. Blur is the compositor's job
  (layer rules). Use plain Rectangles, Canvas and Shape. Gradient Rectangles with a radius get
  jagged corners in software, so use a `Shape` with a `LinearGradient` (see `widgets/WeatherWidget.qml`).
- Popout and overlay contents only exist while open (`LazyLoader`, `Loader { active: … }`), so
  the idle cost is just the bar. Keep it that way: don't create hidden windows that stay alive,
  and don't add timers that run while nothing is shown.
- Animate with `Behavior` / `NumberAnimation`, never with fast timers.

## Colours

- Use `Theme.*` tokens (`Theme.text`, `textDim`, `accent`, `card`, `hairline`, `menuBg`, …), not
  hex. Themes are `themes/<id>.json` with `dark, bg, bg_alt, surface, overlay, fg, fg_dim,
  fg_faint, accent, accent_fg, red, green, yellow, blue, magenta, cyan`. A new file shows up in
  the picker by itself.
- Text colour (`Theme.textMode`) and accent override (`Theme.accentOverride`) are user choices,
  so respect them.
- Desktop widgets take their colours from `widgets/Card.qml` (`fg`, `fgDim`, `cBlue`, `cGreen`,
  `cOrange`, `cPurple`, `cRed`, `cPink`, `cCyan`). These follow Settings → Desktop & Widgets →
  Colours (system / theme / wallpaper; wallpaper comes from `services/WallColors.qml` via matugen).
  An empty string means "use `fg`". Don't add new hardcoded hex colours to widgets.
- Two widget styles: **Tahoe** (frosted, white monochrome, no shadow, because a shadow turns
  into a grey smudge under Hyprland's blur) and **Classic** (material, shadow, colour accents).
  Check both.

## Compositors

- Everything compositor-specific goes through `services/Compositor.qml` (`Compositor.name`:
  `hyprland` / `niri` / `sway` / `mango` / other). A new window or workspace action needs a
  branch for **each** compositor plus a sensible fallback (foreign-toplevel / ext-workspace).
- Mango: dispatch with `mmsg dispatch <func>[,args]` (mango 0.18 rejects `mmsg -d`); query with
  `mmsg get …`; stream with `mmsg watch …`.
- Hyprland uses focus grabs for click-outside-to-close. Elsewhere an open popup puts a
  transparent click-catcher window over the screen.
- Layer surfaces are named `island-<thing>` (`island-bar`, `island-dock`, `island-menu`,
  `island-widgets`, …). Compositor layer rules match on those names, so if you add a surface,
  name it the same way and update the `examples/<wm>/` rules (mango blurs a layer's whole
  surface, transparent parts included, so its Island layers use `no_blur`).

## QML gotchas

- A function or property you add to a base component (`Card`, `SettingRow`, …) can collide
  with a name a child already uses (for example `Card.accent()` vs `CalendarWidget.accent`).
  Grep the children first.
- `Process` + `StdioCollector` for command output; `Quickshell.execDetached` for fire-and-forget.
  Wrap `JSON.parse` in try/catch and `console.warn("island: …")` on failure.
- `FileView { watchChanges: true; onFileChanged: reload() }` to react to state files.
- Canvas items don't repaint on their own when a colour changes. Add a `Connections` that calls
  `requestPaint()`, like the ones in `ClockWidget` / `SystemWidget`.

## IPC

Add a target as an `IpcHandler` in `shell.qml`, then list it in the comment at the top of
`shell.qml` and in README's IPC section.

## Git and backups

- This folder is the git repo. `*.bak`, `*.bak-*` and `*.merged-*` are gitignored, and the owner
  keeps `<file>.bak-<date>-<what>` copies before risky edits. Git history is the real backup:
  don't add new `.bak` clutter for small changes, and don't delete existing ones unless asked.
  Older archives live in `~/dotfiles-archive/<date>/` (machine-local); leave them alone.
- Commit or push only when the owner asks. Commits end with the attribution line the session gives.

## Done means

1. `qs log -c island` shows `Configuration Loaded` and no new `WARN` from your files.
2. You exercised the change (IPC call, open the popout, `grim` screenshot), in both widget
   styles / light and dark if it's visual.
3. If you touched compositor code, it does nothing bad on the compositors you can't test
   (guard with `Compositor.<name>`).
4. README / this file are updated if you added a setting, an IPC target, a dependency or a surface.
